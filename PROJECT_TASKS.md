_Ответственный: Урустемов Рамазан. Дата: 28.10.2026._

## Этап развития

Фильтрация и контроль состояния облачных сервисов.

## Требования

- REQ-01 – API должно поддерживать получение списка сервисов по состоянию.
- REQ-02 – Для поля status допускаются только значения running, maintenance, stopped.
- REQ-03 – При отсутствии параметра фильтрации API возвращает полный список сервисов.
- REQ-04 – Документация API содержит возможность фильтрации и допустимые значения состояния.
- REQ-05 – Пользователь должен иметь возможность искать сервисы по части названия с помощью параметра name: GET /services?name=web. (самостоятельное задание)
- REQ-06 – При передаче недопустимого значения status (в запросе или в теле POST/PUT) API должно возвращать ответ 422 с понятным сообщением, содержащим перечень допустимых значений.

## Критерии выполнения

### TASK-01
- в схеме ServiceCreate поле status имеет тип ServiceStatus (Enum) со значениями running, maintenance, stopped;
- POST /services с status="работает" возвращает код 422;
- POST и PUT с допустимым значением status выполняются успешно (201/200);
- все записи в data/services.py используют только допустимые значения.

### TASK-03
- параметр status является необязательным;
- без параметра API возвращает все сервисы;
- при status=running возвращаются только сервисы со статусом running;
- аналогично работают maintenance и stopped;
- существующий URL /services не изменяется;
- приложение запускается без ошибок.

### TASK-05
- в Swagger UI у GET /services отображается необязательный параметр status;
- для параметра выводится выпадающий список из трёх допустимых значений;
- у параметра есть текстовое описание (description);
- схема /openapi.json содержит enum ServiceStatus.

### TASK-07
- GET /services?status=unknown возвращает код 422, а не 500;
- в теле ответа перечислены допустимые значения running, maintenance, stopped;
- аналогичная ошибка возвращается для POST/PUT с недопустимым status.

### REQ-05 (TASK-09 – TASK-11)
- GET /services?name=WEB и GET /services?name=web возвращают одинаковый результат;
- при отсутствии совпадений возвращается пустой список [] с кодом 200;
- GET /services?name=web&status=running применяет оба условия одновременно;
- запрос без параметра name возвращает полный список.
